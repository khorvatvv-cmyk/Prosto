# Мобильный Android-интерфейс «просто.» — отчёт о переработке

Дата проверки: 03.08.2026

Репозиторий: https://github.com/khorvatvv-cmyk/Prosto

Ветка: `main`

Android package id: `ru.firstbit.prosto`

Версия APK: `1.1.0` (`versionCode 2`)

## Результат

Для клиента создан отдельный мобильный React layout внутри существующего проекта. Он включается:

- всегда внутри Android/Capacitor;
- в клиентском веб-кабинете при ширине меньше 768 px;
- только для роли `user`.

АРМ специалиста, менеджера, РОФ и администратора продолжают использовать существующий desktop layout и существующую бизнес-логику. Отдельного backend или отдельной мобильной базы нет.

Бренд строится вокруг имени `просто.` и коротких спокойных формулировок. Главное обещание первого экрана: «Просто расскажите, что случилось». Технические названия ролей и статусов клиенту не показываются.

## Что было неудобно до изменений

- мобильный экран повторял desktop-структуру: крупный вводный блок, три вертикальные метрики и пять пунктов нижнего меню;
- главное действие конкурировало с показателями и списком;
- вкладки и часть иконок имели область нажатия меньше рекомендуемых 48 px;
- в чате нижняя навигация и поле сообщения занимали пространство одновременно;
- Markdown-ответы ассистента не имели полноценного отображения списков, ссылок и кода;
- создание вопроса выглядело как служебная форма из двух полей;
- статусы были ближе к внутренней терминологии системы, чем к языку клиента;
- не были оформлены состояния отсутствия менеджера, сети, данных и истёкшей авторизации.

Снимки исходного состояния находятся в `docs/mobile-audit/before/`: вход, регистрация, главная, вопросы, новый вопрос, чат, важное, профиль и чат менеджера.

## Что реализовано

### Мобильная оболочка

- светлый интерфейс с фирменным малиновым акцентом;
- header с логотипом `просто.`, уведомлениями и профилем;
- нижняя навигация: «Главная», «Вопросы», «Важное», «Профиль»;
- safe-area сверху и снизу, `100dvh`, отсутствие двойного и горизонтального скролла;
- минимальная зона нажатия 48×48 px;
- полноэкранные чат, создание вопроса, уведомления и детали обращения.

### Главная

- главный сценарий «Просто расскажите, что случилось»;
- заметная кнопка «Задать вопрос»;
- карточка текущего обращения с понятным статусом и новым ответом;
- до двух важных сообщений;
- карточка менеджера или корректное состояние проверки организации.

### Вопросы и новое обращение

- мобильные карточки вместо таблиц;
- поиск и вкладки «В работе»/«Решённые»;
- одно большое поле описания вместо служебной desktop-формы;
- после создания сразу открывается чат;
- данные организации и 1С повторно не запрашиваются;
- кнопка вложения присутствует, но честно сообщает об отсутствии серверного API вложений — фиктивной загрузки нет.

### Чат обращения

- визуально различаются клиент, `просто.`, специалист и системные сообщения;
- Markdown, GFM-списки, ссылки, код и длинный текст отображаются через `react-markdown` и `remark-gfm`;
- компактный прогресс: создано → ассистент → специалист → в работе → решено;
- после ответа ассистента: «Да, помогло» или «Подключить специалиста»;
- после решения специалиста используются существующие серверные действия подтверждения;
- черновик сохраняется в `sessionStorage` при временном переходе/сворачивании;
- composer учитывает экранную клавиатуру и `visualViewport`.

### Важное, менеджер и профиль

- лента «Важное» с категориями «Все», «Новое», «Акции», «Обновления»;
- отдельный менеджерский чат, не смешанный с техническим обращением;
- до подтверждения организации вместо неработающей отправки показано объяснение проверки;
- профиль разделён на пользователя, организацию, 1С, поддержку и настройки;
- показываются статус организации, статус обслуживания и назначенный менеджер;
- разрешённые данные 1С редактируются через существующий API.

### Состояния и Android

- skeleton, пустые состояния, понятные ошибки, повтор загрузки и отсутствие сети;
- глобальная обработка `401`: локальная сессия очищается, пользователь возвращается на вход;
- Capacitor App: предсказуемая системная кнопка «Назад»;
- Capacitor Keyboard: native resize;
- Capacitor Status Bar: светлая системная панель;
- Capacitor Splash Screen: светлый splash без чужой темы;
- версия Android `1.1.0`, package id не изменён.

## Компоненты и источники

21st.dev MCP не был доступен в текущем наборе инструментов, поэтому непроверенные компоненты оттуда в проект не добавлялись.

Отдельный пакет shadcn/ui также не устанавливался. В `MobilePrimitives.jsx` реализованы локальные, доступные и стилистически согласованные примитивы на тех же UI-паттернах: Button, Badge, Tabs, Avatar, Skeleton, Empty/Error state. Для иконок используется уже существующий `lucide-react`. Это исключает Next.js-зависимости и не добавляет Radix-пакеты ради простых мобильных элементов.

Правила поведения сверялись с Material Design 3: touch target 48 px, четыре пункта bottom navigation, безопасные зоны, системная кнопка назад, экранная клавиатура и светлые системные панели.

## Playwright-проверка

| Сценарий | Результат |
|---|---|
| Регистрация нового клиента и заполнение профиля | пройден |
| Создание нового вопроса, открытие чата и ответ ассистента | пройден |
| Передача специалисту и смена клиентского статуса | пройден |
| Ответ специалиста и финальное подтверждение | не завершён: в тестовой среде не было активного специалиста |
| Раздел «Важное» | пустое состояние пройдено; активной кампании для действия не было |
| Чат менеджера | корректно показана проверка организации; ответ менеджера недоступен без подтверждённой связи |
| Редактирование и сохранение профиля | пройден |
| Уведомления и переход к обращению | пройден |

В production D1 во время авторизованной проверки были созданы отдельный тестовый клиент и тестовое обращение. Пароли и токены в репозиторий и этот отчёт не записывались.

Проверенные размеры:

- 360×800 — `scrollWidth = 360`;
- 390×844 — `scrollWidth = 390`;
- 412×915 — `scrollWidth = 412`.

Горизонтального переполнения нет. Composer чата заканчивается ровно у нижней границы viewport. Основные кнопки и нижняя навигация имеют высоту не меньше 48 px.

Desktop-клиент проверен интерактивно при 1440×900. Разделение mobile/desktop и доступы сотрудников проверены тестами. Полный интерактивный вход в АРМ L1, менеджера, РОФ и администратора не выполнялся, потому что их тестовые учётные данные не передавались.

## Известные ограничения

- сервер пока не принимает вложения, поэтому кнопка прикрепления не имитирует загрузку;
- push-уведомления Android не настроены: текущие уведомления загружаются из API при открытии приложения;
- окончательный сценарий со специалистом требует активного сотрудника L1;
- менеджерский диалог требует подтверждённого членства клиента в организации и назначенного менеджера;
- собран debug APK, не магазинный release.
